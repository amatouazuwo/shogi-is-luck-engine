# C2 障害物局面の3手安全確認

穴対応SDKのベース `ae8d8effdb04b6b0e9f1a73a03cfafbd41843e67` に敗着ガード初版、全幅3手検査の代替手安全修正、C2の順で重ねる。C2は初版・安全修正と同じWorkerと内蔵モデルを使う。通常盤面の固定ノード探索14件で指し手・評価値・深さ・ノード数・読み筋が一致した。

代替手の最終攻撃手を調べる際、守備側が持つ歩以外の駒に対し、二つ以上の空いた合法な打ち先があるかを調べる。攻撃側の一手が使用できる打ち先を塞ぐのは最大一つで、守備側の持駒も減らない。王手をかけない手の後には少なくとも一つ合法な打ち手が残るため、この条件下では最終手の王手だけを詰み候補として確認する。桂馬と香車には行き所のない段の制限を適用する。条件が成立しない場合と、それ以前の手には全合法手を調べる。評価値が同じ代替手は、置換表で確認した探索深さを順序決定に使う。

12,000ノード上限、時間上限、詰み負け評価の代替手拒否、時間切れ時の元手維持を保つ。ガードが使う時間は100ms設定で最大12ms、500・1500ms設定で最大24msで、元の思考時間の内数。全幅3手検査が確定した代替手だけを採用し、4手目以降の安全性は検査の対象外。実測値はCPU負荷で変動する。

## 既知局面と配布物の確認

- Rustの専用テスト4件に合格。落とし穴・ブラックホールの固定乱数局面で、打ち手を根拠にした確認と全幅の結果が一致した。二つの打ち先を確保できない局面と、旧ガードがより短い詰み負けを選んだ回帰局面も含む。
- 保存落とし穴 `pit-100:16` の `L*4a` から、独立検証の回避手 `5a5b` に24msの試験で変更した。2,412ノードのうち安全確認2,143、持駒の打ち先で判断した末端218。12msと35msは同実行で時間切れ。別の同ソース実行では三つの予算で2,412ノードで完了した。全幅安全修正の版は、12,000ノード上限でこの代替手を確定できなかった。
- 保存ブラックホール `blackhole-500:70` の `9c9d` は32ノードで敗着と判定した。守備側に使える非歩持駒の条件が成立せず、時間またはノード上限までに代替手を確定できなかった。
- 実Workerの穴1・9のスモーク、全7ファイルのSHA-256照合に合格。データと結果は `archive-probes.jsonl`、`native.log`、`smoke.log`、`zero-control.jsonl`。
