# 暫定25,000ノードCPU：特殊盤面の相対実力検証（2026-11-23）

## 位置づけ

ユーザー指定の開発用ルール「技巧2 v2.0.2、探索深さ8＝アマ四段程度（仮）」を通常将棋で比較した結果、rsshogi 25,000ノード（1手最大1秒）は未使用の通常開始局面ID14・15による4局で2勝2敗だった。**25,000ノードは開発用候補であり、対人アマ四段の認定値ではない**。公式技巧2の評価ファイル `params.bin`、`progress.bin`、`probability.bin` を全て揃えた再測定のみを採用する。参照：[校正文書](gikou-three-model-calibration-20261123.md)。

特殊盤面には技巧2を適用できないため、**同一障害物対応rsshogi NNUEのノード上限だけを変える相対比較**を実施した。ゲーム難易度そのものは変更しない。

## 完了した本物の特殊盤面対局

検証先：[GitHub Actions #45138548316](https://github.com/amatouazuwo/shogi-is-luck-engine/actions/runs/45138548316)、**2ジョブともSUCCESS**。各ジョブ内で双方同じWASM/Workerを使用し、独立C++審判で全手の合法性・時計・勝敗を検査した。

| 25,000ノード対戦相手 | 25,000勝 | 相手勝 | 未決着（中立） | 25,000側の得点下限～上限 |
|---|---:|---:|---:|---:|
| 10,000ノード | **13** | 8 | 3 | 54.2～66.7% |
| 50,000ノード | 6 | **14** | 4 | 25.0～41.7% |

各比較24局。6元局面（21～26）×落とし穴／ブラックホール×先後交換。序盤系・中盤系・駒数少の各8局を含む。双方3分時計、1手最大1000ms、最大深さ64、時計残量÷20、着手前待機1300msを**仮想的に時計から減算**。300手到達と千日手未裁定は引分・敗北へ変換しない。

| 盤面別（25,000側） | 対10,000ノード | 対50,000ノード |
|---|---|---|
| 落とし穴12局 | 7勝5敗 | 4勝6敗・未決着2 |
| ブラックホール12局 | 6勝3敗・未決着3 | 2勝8敗・未決着2 |
| 序盤系8局 | 4勝4敗 | 4勝4敗 |
| 中盤系8局 | 7勝1敗 | 1勝7敗 |
| 駒数少8局 | 2勝3敗・未決着3 | 1勝3敗・未決着4 |

同じエンジンで探索ノードだけを変えた**今回の小規模条件では、25,000ノードの強さが10,000と50,000の間に位置するという傾向が出た**。ただし各比較で使った元盤面は6個に限られ、データには相関がある。25,000側は10,000側との中盤系で勝ち越し、50,000側との中盤系で負け越した。終盤一般の強さ、Elo、アマ段級位は導けない。

両ジョブは別々にWASMをビルドしている。**それぞれのジョブ内で同じWASM/Worker**を照合したが、ジョブ間のビルドSHAは異なるため、2ジョブの絶対速度や評価値を直接比べない。

新規障害物マスクの6元局面×2障害物×先後交換で、25,000対10,000と25,000対50,000を**各24局・計48局**比較する。いずれも最大300手・同じ3分時計・1手1秒・同じWASM/Worker。全24局の欠落、初期SFEN／障害物の混同、実探索ノード超過、評価用モデル不一致、未決着の勝敗化を自動検出する。成果物容量を節約するため棋譜JSONLと得点表はGitHub Actionsログ・Job summaryで確認し、重いバイナリや外部評価ファイルは再配布しない。

**追試の結果が出るまで改善・悪化を確定しない。** 正式なCPU設定、簡易CPU「ふつう」、ゲーム側Draft PR #12、ゲームの`main/develop`およびRender本番は変更しない。実装と文書はエンジン側Draft PR #3（`chatgpt/strength-ci`）に限定する。

## 障害物配置を新しくした48局：結果確定（2026-11-23）

[追試 GitHub Actions #45141593863](https://github.com/amatouazuwo/shogi-is-luck-engine/actions/runs/45141593863)：**両ジョブSUCCESS、合計48局を完走し、全手合法性・持時計・WASM/Worker一致・探索上限・元局面および障害物配置の監査も成功**。

シード`20261211`で落とし穴・ブラックホールの新しい配置を生成（6元局面×両障害物×先後交換）。**出発点の通常SFENは既存の収録局面**なので、別の完全未使用ゲーム初期陣形の実証ではない。

| 25,000ノード側の対戦相手 | 25k勝 | 相手勝 | 中立未決着 | 得点下限～上限 |
|---|---:|---:|---:|---|
| 10,000ノード | **18** | 3 | 3 | 75.0%～87.5% |
| 50,000ノード | 8 | **15** | 1 | 33.3%～37.5% |

障害物別：
- 25k対10k：落とし穴10勝2敗、ブラックホール8勝1敗・未決着3。
- 25k対50k：落とし穴4勝8敗、ブラックホール4勝7敗・未決着1。

先の既存配置48局と今回の新配置48局を単純に合計すると、25k対10k＝31勝11敗・中立6、25k対50k＝14勝29敗・中立5。ただし同一または関連する開始局面の再使用や先後交換による相関があるので、**96局を独立標本として統計的な段級位保証に使わない**。

当該結果に基づく判断は**25kを「アマ四段程度（仮）」の暫定開発候補として継続**。ゲームCPUの正式変更・段位認定・本番適用は行わない。

### 次のギャップ：既存のゲーム「アマ四段を目標」とは探索条件が異なる

ゲーム側Draft PR #12の現行`am-yondan`はrsshogiの**1手最大1500ms・ノード上限なし**（残時計÷20・最大1300ms着手前待機）。しかし、今回の「仮四段基準25kノード」は**1手最大1000ms・上限25,000ノード**。どちらも同じNNUEであっても、**棋力は同等とは限らない**。

そこで[検証専用ワークフロー](../.github/workflows/provisional-fourdan-versus-game-profile.yml)を追加。落とし穴とブラックホールを含む3元局面×先後交換の**12局**を同一WASM/Worker・同じ3分時計・最大300手で直接比較し、合法手／探索ノード／時計を監査する。これが完走してから結果を解釈する。1秒と1.5秒に加えてノード制限の有無も違うため、**純粋な「思考時間だけの効果」ではない**。

今後、4段目標のCPUに上限ノードを実装するかどうかを検討する際は、実ゲームChromiumのCPU着手・時計・キャンセル・1%特殊イベント・スマホ相当条件も再検証する。**この文書を書いた時点でゲーム側のコード、Draft PR #12、main/develop、Renderには何も変更していない。**
