**新ビルドAとBでもバイト数・ハッシュが異なった。** これは少なくとも**このビルド手順でバイト列が再現できていない**ことを示す。原因（非決定的なメタデータ・ビルド環境差・コンパイル出力差など）は未特定。差異が「コードの意味に影響しない」かもまだ未検証で、両者の機能・性能が完全同一とは保証しない。

[元の#45188420789](https://github.com/amatouazuwo/shogi-is-luck-engine/actions/runs/45188420789)の独立監査に「exact private-game pinned NNUE WASM/Worker」という不正確な成功文言が残ったため、**#45188961908では修正**し、「実WASMブラウザ検証は成功。ただしゲームのWASMとバイト列不一致」と正しく表示する。

## 検証範囲の限界と開発判断

- **PASS：** 同じ固定ソースから生成されたSDKの本物のWASMと、本物のChromium Web Workerの通信・合法手・障害物・ノード上限・強制終了と再作成。
- **未検証：** ゲーム側にコミットされているWASMそのもののブラウザ挙動、ゲームの index.html／CPU難易度画面、3分時計、特殊1%イベント、端末差、実オンライン対局。
- **保護：** ゲームの現行CPU5段階、簡易CPU「ふつう」、仮段級位、main/develop、Render本番のいずれも変更しない。ゲームの保存済みWASMを再ビルド版に勝手に差し替えない。PRをマージ・デプロイしない。

次の技術課題は、**WASMのセクション差を比較してビルドの非再現性を調べる**こと、およびゲームプライベートリポジトリのRunner復旧後に保存済みWASMでブラウザ試験を行うこと。

## 同じGitHub Runnerでの独立2回ビルド：非再現性の中身を確認（2026-11-23）

[セクション比較 #45190443518](https://github.com/amatouazuwo/shogi-is-luck-engine/actions/runs/45190443518)は全工程SUCCESS。両ビルドはRust 1.95.0・固定ソース・同じRunner、同じビルドスクリプト。両WASMは内部のSDK SHA256SUMS照合にPASSし、6件のバイナリ比較プログラム単体テストもPASS。生成WASMのサイズは**4,962,687バイト対4,962,684バイト（3バイト差）**だった。

[次の2回ビルド＋実探索比較 #45191054468](https://github.com/amatouazuwo/shogi-is-luck-engine/actions/runs/45191054468)もSUCCESS。生成WASMは**4,962,702バイト対4,962,704バイト（2バイト差）**。どちらの実行でも、下記セクションにバイト列の差があることを確認した。

| WASMセクション | 2回のビルド間で一致するか |
|---|---|
| custom:name（関数名等） | 不一致 |
| type（関数シグネチャ） | **不一致** |
| function（関数定義の並び） | **不一致** |
| element（関数テーブル等） | **不一致** |
| code（関数の実装バイト列） | **不一致** |
| data（静的データのバイト列） | **不一致** |
| import / export / memory / table / global / producers / target_features | 一致 |

これは**付属メタデータだけの差異ではない**ことの証拠。ただし関数インデックス等の再割当によって同じ処理を表す異なるバイト列になる可能性もあり、コードの不一致だけで探索アルゴリズムや強さが変わったとは言えない。

### 異なる2バイナリのネイティブ探索結果：6条件で完全一致

[固定ノードの実NNUE探索 #45191054468](https://github.com/amatouazuwo/shogi-is-luck-engine/actions/runs/45191054468)で、同じ2つのWASMを**同じNode.jsプロセス**で初期化し、通常将棋・落とし穴・ブラックホールの3条件×探索ノード上限5,000/25,000の計6条件を実行した。

**6条件すべてで合法手の集合・選択した指し手・ノード数・深さ・評価値・読み筋が一致した（6/6、差異0）。** 探索時間ではなくノード数で制御し、実行時間の揺らぎを比較条件から外した。

[実探索比較スクリプト](../benchmarks/strength/ci/wasm-behavior-diff.mjs)および[WASM構造比較プログラム](../benchmarks/strength/ci/wasm-section-diff.mjs)を追加。バイナリ構造比較は正常・異常・メタデータ差・コード差・データ差を区別する6テストを備える。

**結論と制約：** 少なくとも今回の6局面×ノード条件では、バイト列の差が実際の探索結果の差として表れていない。しかし**全局面の意味的同等性を証明したわけではない**。また今回比較した2本は新規ビルド同士であり、プライベートゲームに保存済みのWASMそのものは含まない。人間の段級位・既定CPU時間・本番への導入判断もこの検証からは変えない。

次の調査候補は、内部関数の並び替えやビルド時の非決定性をさらに追跡し、可能なら**ゲームに保存された正確なWASM**で独立なブラウザ実対局試験を行うこと。別ソースのビルド物をゲームへ自動置換しない。
