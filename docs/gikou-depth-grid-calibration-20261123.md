# 技巧2とrsshogiのノード数・探索深さの実対局校正 第2段階

## 目的（2026-11-23）

前工程の[実技巧2深さ2との16局](https://github.com/amatouazuwo/shogi-is-luck-engine/actions/runs/45112753268)では、ノード500のrsshogiが1勝7敗、ノード10,000が8勝0敗だった。そこで今回、**中間ノード上限の実力帯を絞り込み**、さらに深い技巧2に対して強い候補の対局テストも始める。

**実際の人間のアマ5級／初段／四段に対応させる校正は未完了であり、ゲーム中の段級位設定をここでは一切変更しない。**

## 対局条件（結果を見る前に固定）

|---|---|---|---:|

| **計** | | | **96** |

いずれも通常将棋のみ。特殊盤面では技巧を使用しない。Gikou2公式v2.0.2タグのソースコミット`f5773abb6b93c53508bca4d6d5705463e56ccb0f`からビルドした本物のUSIエンジンを使用し、公式ZIPおよび`params.bin`の既知のSHA256ハッシュを検証。技巧は`DepthLimit`を設定、定跡オフ、単一スレッドで`go depth N`を送信。rsshogiは本物のWASM NNUEの`depth=64`,`nodes=設定上限`,`movetime_ms=最大1000`で対局。

双方の持時計180秒、1手ごとに1300ms着手前待機を仮想減算、残時計÷20を用いた手当をrsshogiに適用。**技巧の制御は深さであって、rsshogiと同じ1秒上限を技巧には強制していない**。時計残量は双方で消費時間を計上するが、厳密に同じ最大思考時間の比較ではない。これは棋力を評価する際の明示的制約。

最大300手到達、千日手の未裁定、宣言勝ち不対応等は**中立未決着**。敗北や引き分けには自動変換しない。合法手は独立C++審判との照合。各組で先後を入れ替え、同じ開局局面から比較。元の局面8～15は過去の開発データからの再利用であり、未知の未公開評価セットではない。

## 実装

- `benchmarks/strength/ci/external-usi-depth-grid-match.mjs`：実Gikou2深さ2～5、rsshogiノード上限一覧、平手元局面IDを入力として、各局面・各ノードの先後交換付き実対局を実行する専用ハーネス。既存の実対局コードや本番ゲームは変更しない。
- `benchmarks/strength/ci/external-usi-depth-grid-scorecard.mjs`：全対局の実測棋譜、Gikouの固定公式パラメータ、rsshogiのモデル・Worker SHA、元資料SHA、先後交換、時計消費、探索ノード、未決着処理を独立検証し、ノード上限別と先後別の勝敗・平均探索時間を集計。段級位自動認定を拒否。
- `benchmarks/strength/ci/external-usi-depth-grid-scorecard.test.mjs`：時計や棋譜の改ざん、探索上限逸脱、偽の敗着・勝敗、対象の欠落、定跡設定の変更を検出する単体テスト。
- `.github/workflows/gikou-depth-grid-calibration.yml`：2つのGitHub Actionsジョブ。実際のGikou2とrsshogiをピン留めビルドして計96局を自動比較し、JSONLログと採点サマリーを保持。評価パラメータや実行ファイルはアーティファクトとして再配布しない。

## 結果の解釈

- 勝率が50%前後に近いノード帯を発見した場合、**「技巧2深さ2に対して互角付近」**という意味であり、無条件のアマ5級相当という意味ではない。
- 勝率・Eloの推定には十分な異なる盤面と複数回の対局が必要。前工程と同じ元盤面を使う部分は相関がある。中間ノード値を今度の結果に合わせてさらに狭めた場合、後で**完全に別の局面セット**を使って検証する必要がある。
- 技巧2の歴史的な「将棋倶楽部24 5級・初段・二段程度」という表示は現代の人間アマ段級位とは同一でない。深さ5は現時点では「アマ四段を検証した」根拠にならない。
- 特殊盤面での強さの順序・参考指し手一致率は別の検証として残し、通常将棋での棋力換算とは区別する。

正式のCPU難易度5段階（「ふつう」は簡易CPU）、`main/develop`、ゲームDraft PR #12、Render本番は変更しない。エンジンDraft PR #3の独立した検証プログラムと文書だけを更新する。
