# 「王手への応手が少ないほど6秒長考する」の根拠検証（2026-11-23）

## 質問と結論（検証前）

「王手への応手が3通り以下なら6秒」は開発初期の仮説であり、将棋理論や実測で正当化したルール**ではない**。候補手が少ないぶん、探索の初手の枝分かれ数は減り得るので、1〜3秒でも十分に読みが進む可能性がある。ただし、その後の変化は多くなり得るし、王手を受けた局面では読みを間違えた際の損失が大きい。**合法応手数だけで必要探索時間を決定するのは過度に単純**。

このため「危ない局面ほど6秒」という設計意図だけでは採用しない。現行の正式CPU設定とv2の元コードは維持し、検証専用のv2-check3sを作る。

## 対照実験

- **対照 v2**：`inCheck && legalCount <= 3` なら思考予算最大6000ms
- **変更 v2-check3s**：同じ条件で思考予算最大3000ms
- その他のv2の局面判定、時計の安全制限、最大6秒、WASMモデル、Worker、3分時計、1300ms着手前待機、探索予算時計分母12は**すべて同一**。両側とも局面特徴計算にかかった時間を各自の時計へ計上。
- 読み切れるか、詰みを見逃すか、実戦の勝敗、時間切れ、終局時残時計、平均探索深さ、**対象条件が実際に何度発生したか**を計測する。特徴量は独立C++合法手審判から取得。
- 新しい障害物配置シード20261213。異なる通常将棋の開始盤面2種類（コーパス内の`game`系・`hirate`系から1つずつ）、各々に穴1個・ブラックホール3×3を配置し先後入替。**各盤面群4局、全体8局**。GitHub Actionsは別jobで並列、各jobの完了と時計・合法手監査を確認。
- 最大300手で未決着なら**中立**。これまでの小標本の勝敗で棋力・アマ段級位・「必ず6秒不要」とは認定しない。
- **注意**：v2-check3sが元v2と違うのは対象条件が発生したときだけ。もし対象条件がほとんど発生しなければ、勝敗差なしは**3秒でも十分という証拠にはならない**。より多くの局面・戦術問題での再試験が必要。

## 先行して確認できた成績（別の比較）

可変思考v2と固定1秒は新規障害物配置の4局で2勝2敗、v2とv1は1勝3敗。v2はv1よりも残時計を節約したが勝ち越せなかった。したがって、「王手への応手少数なら6秒」という元の局面判断が棋力向上に有益という根拠はない。ただし、その差だけが敗因だったとも主張できない。
